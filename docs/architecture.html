01 · Context

总览与约束

OrbitWork v1 是一个单节点、可私有化的 Web 应用。设计约束按优先级排序：

低运维成本

一个 ECS、一个数据卷、一个 Compose 文件；不要求 RDS、Redis、对象存储或 K8s。

租户边界

所有对象查询带 workspace_id；会话再带 user_id；越权返回 404。

安全默认

密钥不回流、插件不执行代码、沙箱无网络、管理员不读私有会话。

可测试

Fastify inject + node:test，不依赖浏览器、网络或外部数据库。

可演进

domain / application / infrastructure / http 分层；SQLite 可迁移到 PostgreSQL。

交付速度

esbuild 全量构建约 150–300ms；无 Tailwind/Vite 运行时工具链。

02 · ADR

关键技术决策

决策选择理由与代价
架构风格模块化单体单机部署最小化；比微服务少 10+ 个运维面。代价：需要靠代码边界与测试维持纪律。
数据库node:sqlite + WAL零外部依赖、备份简单、ACID。代价：单写者、水平扩展受限。
认证不透明会话 + SHA-256可即时撤销、无 JWT 密钥轮换问题。代价：每请求一次 DB 查询（已索引）。
前端React SPA + esbuild构建快、控制力强。代价：没有 SSR/SEO，不适用于公开内容站。
LLMOpenAI 兼容网关可替换供应商，兼容 DeepSeek/Qwen/vLLM。代价：仅覆盖 Chat Completions 语义。
沙箱文件队列 + network:none worker无共享网络、无 Docker socket、无凭据。代价：仅串行、需共享卷、延迟约 120ms 轮询。
市场统一 assets 聚合 + 版本快照四种资产共用生命周期与 UI；安装不受发布者后续修改影响。代价：payload 多态需要严格 schema。

06 · Isolation

租户与权限不变量

I1 工作区先行

每个租户对象的读取/修改都显式带 workspace_id；子资源查询同时带 id 与租户。

I2 404 优先

无成员关系或对象跨租户时返回 404，避免暴露存在性。

I3 会话私有

chat 读取/列表/流式/删除都带 user_id；overview 也只统计自己的会话。

I4 对象级授权

成员只能改自己创建的 agent/asset/memory；管理员/所有者可治理。

I5 角色上限

邀请角色不能超过邀请人；所有者不可被降级/移除；最后一名平台管理员不可降级。

I6 平台边界

平台管理员可审核内容与重置密码，但没有读取用户会话的 API。

测试包含“外部工作区访问全部 404”“同工作区另一个成员读不到私有聊天”“overview 不泄漏他人会话标题”“成员不能改他人智能体记忆”等回归项。

07 · AuthN

认证与会话

  • 密码：scrypt，16-byte salt，64-byte 派生；常量时间比较；最少 12 位。哈希格式 scrypt$salt$hash。
  • 会话：32 字节随机令牌，数据库只存 SHA-256；Cookie orbit_session HttpOnly/SameSite=Lax/Secure（生产）；14 天绝对过期。
  • 登出/改密：删除当前/其他会话；管理员重置会删除该用户全部会话。
  • CSRF：SameSite + Origin 白名单 + JSON Content-Type；无 token 方案，避免 SPA 额外复杂度。
  • 速率：IP 30/10min + 账号 8/10min 登录；注册 5/10min；聊天 12/min；沙箱 10/min。账号键独立于 IP，抗 IP 轮换。
  • 代理信任：默认关闭；Compose 只信任 loopback / link-local / 私网地址（Caddy 所在网络），不信任公网直连的 XFF。
08 · Model configuration

模型与 Provider

模型选择从部署环境变量升级为工作区级可配置能力。数据模型新增 providers 与 workspace_models（migration v5）；工作区所有者/管理员可添加 OpenAI 兼容 Provider、模型与默认项，成员仅能读取有效模型列表。

providers
  id, workspace_id, name, type(openai-compatible), base_url,
  api_key_encrypted(v2 AES-GCM + AAD workspace:provider), enabled, created_by
workspace_models
  id, workspace_id, provider_id FK CASCADE, model_id, label,
  context_window, enabled, is_default, created_by
  unique(workspace_id, model_id); partial unique default per workspace

resolution:
  enabled workspace_models + enabled provider
    → base_url + decrypted key + context_window
  zero workspace_models → env LLM_* fallback (平台默认)
  configured but none enabled → no model (never silently use env)

Runtime: resolveWorkspaceModel() returns provider/base URL/key/context window/demo state. streamModel() receives an explicit adapter config for workspace providers; the default env adapter is used only for the platform fallback. Context trimming uses the selected model’s context_window, not a global value. Provider URL is checked at save and again before every request; redirects are rejected. Keys are write-only, encrypted with AAD, and never placed in API responses, audit metadata or trace payloads.

Defaults: deleting a model/provider clears/repoints the workspace default in the same transaction; the partial unique index prevents multiple defaults. Provider test uses GET /models with an 8s timeout and no redirect following.

09 · Runtime

智能体运行时

POST /api/w/:ws/chats/:id/messages
  │ requireWorkspace + chat.user_id + rate limit
  │ 持久化 user message + run(running)
  │ hijack → SSE
  ├─ meta { runId, model, demo }
  ├─ buildSystemPrompt(agent, skills, memories, workspace)
  ├─ model call #1  ──stream──► delta / reasoning
  ├─ tool_calls? execute → tool event → tool message → model #2..#3
  ├─ persist assistant message, usage, run(complete/error/cancelled)
  └─ SSE done | error

提示词组装

系统提示 = 智能体名称/角色指令 + 工作区名称/日期/用户 + 已绑定技能指令 + 相关记忆（最多 6 条）+ 行为准则。工具输出被标记为不可信外部数据。v1.3 起历史按 token 预算裁剪（`server/domain/context.ts`：CJK≈0.7 token/字、ASCII≈0.25，固定首条 user，旧工具结果压成一行），工具循环默认 6 步（`AGENT_MAX_STEPS`，上限 12），达上限在回答中显式提示。

LLM 接入层（v1.3）

server/infrastructure/llm.ts 暴露单一 LlmPort（stream(options) → ModelResult），调用方零改动。LLM_ADAPTER 只切两个能力位：legacy 仅读 reasoning_content 且不重试；port 归一并归一 reasoning / thinking / thought，并在**首包前**对 429/5xx/网络错误重试最多 2 次（指数退避、尊重 Retry-After，流一旦开始则不再重试）。usage 统一为 input / output / cachedInput。

工具

  • save_memory / search_memories：仅在智能体开启记忆且工作区未关闭记忆时暴露。
  • run_javascript：仅在智能体与工作区均开启沙箱时暴露；调用独立 worker。
  • 连接器：每个绑定连接器生成一个函数工具，schema 来自资产 payload。

轨迹消费（v1.3）

新增 model.done 事件，用于把模型耗时与工具耗时分开归因；GET /chats/:id/trace 返回 metrics（总耗时 / 模型 / 工具 / 首 token），/trace/export?format=json|md 以附件形式导出。

失败与取消

运行前写 run 记录；取消调用 POST /runs/:id/cancel 触发 AbortController；客户端断开同样中止。无论成功/失败/取消，finally 都会落库助手消息（允许空内容 + 状态），并清理运行表。服务重启时所有 running 被置为 cancelled，避免会话永久锁死。

11 · Marketplace

市场、版本与安装完整性

publish:
  validate(kind,payload) → snapshot JSON → sha256 → asset_versions
  assets.status=published, visibility=public

install:
  source must be published+public
  read latest asset_versions snapshot
  re-validate snapshot (never trust request body)
  transaction:
    clone asset (status=draft, visibility=private)
    if plugin: clone ≤10 children
    insert asset_installs(source_version)
    increment installs

delete clone:
  remove install row + decrement source installs (same tx)
  → reinstall works

连接器 secrets 永远不进入 payload_json：仅通过 secrets 字段写入 secrets_encrypted（AES-256-GCM）。市场序列化再次剥离 headers；插件快照中的连接器同样无凭据。安装时源资产 secrets 为零。

12 · Sandbox

沙箱威胁模型

入口仅 app 写入 /jobs/inbox；job 含 code 与 id
执行worker 串行取任务；child node --permission；临时目录只读输入
出口/jobs/outbox JSON；stdout/stderr 截断；6 秒超时

隔离控制

  • Compose：network_mode: none、read_only: true、tmpfs /tmp、cap_drop: ALL、no-new-privileges、pids 128、memory 256m、cpus 0.5。
  • 容器不挂载数据库；不注入 APP_SECRET、LLM Key、SANDBOX_TOKEN（队列模式完全不需要）。
  • Node 权限模型：仅允许读取 /tmp 与一次性目录；禁止 fs 写入、child_process、worker、addon 等（Node permission model）。
  • 应用层：代码 ≤20KB、用户级 10 次/分钟、工作区开关、全局串行。

残余风险

worker 自身是可信代码；Node 权限模型不等于内核级沙箱，内核漏洞逃逸仍是理论风险。高合规场景建议替换为 Firecracker/gVisor 或独立节点执行。V1 不提供 Python/npm 包能力。

13 · Network & files

联网与文件子系统

两个能力都实现在 app 进程内，沙箱保持 network:none。这样不破坏既有威胁模型，也不引入新依赖（上传走 raw body，未引入 multipart）。

数据与存储

migration v3 新增 files 表（16 → 17 张表），以 UNIQUE(workspace_id, name) 表达「同名覆盖」。磁盘布局为 <DATA_DIR>/files/<workspaceId>/<fileId>；落盘名是 UUID，展示名只存元数据，因此路径穿越在结构上不成立。

CREATE TABLE files (
  id TEXT PRIMARY KEY,
  workspace_id TEXT NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
  chat_id TEXT REFERENCES chats(id) ON DELETE SET NULL,
  name TEXT NOT NULL, mime TEXT NOT NULL, size INTEGER NOT NULL,
  sha256 TEXT NOT NULL, storage_key TEXT NOT NULL, text_preview TEXT NOT NULL DEFAULT '',
  created_by TEXT NOT NULL REFERENCES users(id),
  created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL,
  UNIQUE(workspace_id, name)
);

Browser ──octet-stream──► POST /api/w/:ws/files?name=&mime=
                            └─ 开关 → 名字规整 → 配额 → 写盘(temp+rename) → DB 行 → 审计

Agent ──write_file──► putFile()（同上，同名覆盖）
Agent ──read_file───► 文本前 100KB 窗口 → 按 offset 分页 7.6k 字符

                       → 手动重定向（≤3 次，逐跳复检）
                       → 1MB 截断 / 15s 超时
                       → HTML→文本 / JSON 美化

安全控制与残余风险

控制实现残余风险
SSRFIPv4 非全球单播全拒；IPv6 覆盖 ULA / link-local / site-local / multicast / NAT64 / 6to4 / Teredo / IPv4-mapped；URL 内嵌凭据拒绝；web_fetch 强制 allowPrivate:false，不受 ALLOW_PRIVATE_CONNECTORS 影响DNS rebinding 的 TOCTOU 仍存在（校验与连接各解析一次）；彻底修复需 connect 阶段固定 IP
重定向不使用自动跟随；每一跳重新走守卫，最多 3 跳—
体积/时间响应 1MB 截断并取消流；15s 超时；文本 20k 字符上限解压炸弹依赖上游 Content-Encoding 行为
上传仅 /api/w/:ws/files 接受 octet-stream；单文件 5MB；文件名去路径与控制字符仅单实例限流，无全局磁盘水位告警
下发全局 nosniff；HTML/SVG 强制 attachment；图片 inline 但带 filename图片解码漏洞取决于浏览器
注入文件名不进系统提示；抓取/文件内容统一标注为不可信数据模型仍可能被内容诱导，需人工复核高风险动作
租户所有路由 requireWorkspace；跨工作区 404；删除工作区时清理 FILES_DIR/<ws>—

开关与可观测

filesEnabled / networkEnabled 存于 workspaces.settings_json，默认开启。关闭后：运行时不再注册对应工具；文件路由返回 403。审计事件为 file.upload / file.delete，web 抓取计入每次 run 的 toolEvents（含 URL、状态、字节数）。

测试

新增 23 项测试（文件 API 11 项、领域规则 5 项、SSRF 表格与重定向 2 项），全套 71/71 通过；typecheck 与生产构建通过。生产构建下实测：上传 → 列表 → 文本预览 → 下载头 → 磁盘 UUID 落盘 → migration v3；web_fetch 对 example.com 返回 200 并抽取标题，对 127.0.0.1 / 169.254.169.254 / [::1] 全部 PRIVATE_URL。

14 · Trace & thinking

可观测性：轨迹与推理

轨迹是 append-only 的元数据事件流，写入与 SSE 推送同源；推理文本只保留最终结果与耗时，不保存逐 token 流。

数据模型（migration v4）

CREATE TABLE trace_events (
  id TEXT PRIMARY KEY,
  workspace_id TEXT NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
  chat_id TEXT NOT NULL REFERENCES chats(id) ON DELETE CASCADE,
  run_id TEXT, seq INTEGER NOT NULL,
  kind TEXT NOT NULL, phase TEXT NOT NULL DEFAULT '', status TEXT NOT NULL DEFAULT 'ok',
  duration_ms INTEGER NOT NULL DEFAULT 0, detail_json TEXT NOT NULL DEFAULT '{}',
  created_at INTEGER NOT NULL,
  UNIQUE(chat_id, seq)
);
ALTER TABLE messages ADD COLUMN run_id TEXT;              -- 回答 ↔ run
ALTER TABLE messages ADD COLUMN reasoning_ms INTEGER;     -- 思考耗时（按模型调用累计）

采集顺序与失败语义

run.start → prompt.ready → model.call → model.first_token
  → tool.call (0..n, 含 web_fetch / read_file / write_file) → run.done | run.error
  • 写入失败只记 console.error，不阻断流式；seq 由 MAX(seq)+1 生成，并由 UNIQUE(chat_id, seq) 兜底。
  • 每会话上限 1000 条，超出即删除最旧一条；超过 1000 条时 API 返回 truncated 与 totalEvents。
  • reasoning_ms 按每次模型调用累计，工具执行时间不会计入「已思考」。

15 · Connectors

连接器安全

  • 协议：仅 HTTP/HTTPS；GET 参数拼接 query，POST 发送 JSON；12 秒超时；不跟随重定向。
  • SSRF：禁止 localhost、私网、link-local、云元数据、IPv4/IPv6 私网；域名解析后再次校验；生产默认不可访问内网（ALLOW_PRIVATE_CONNECTORS=false）。
  • 凭据：AES-256-GCM，密钥由 APP_SECRET 派生；API 只返回 key 名；市场与安装快照不含密钥。
  • 输出：响应上限 100KB，工具输出再截断 8KB；作为不可信数据注入。
  • 配置：工具名限制为函数名格式；参数 JSON Schema 由发布者提供并校验。

Docker 本地与阿里云部署

本地一键启动

最小规格

  • ECS 2 vCPU / 4 GB（最低 2 GB）
  • Ubuntu 24.04 LTS，磁盘 40 GB ESSD
  • 安全组仅开放 22、80、443
  • Docker Engine 24+ / Compose v2
  • 一个域名解析到 ECS（大陆需备案）

生产环境变量

  • APP_ORIGIN=https://your.domain
  • SITE_ADDRESS=your.domain
  • COOKIE_SECURE=true
  • APP_SECRET ≥32 随机字符
  • SEED_DEMO=false，强密码
  • LLM_API_KEY 与模型列表

运维、备份与恢复

备份

# 立即备份（容器内）
docker compose run --rm app node dist/backup.js
# 宿主机定时任务（示例：每天 03:20）
20 3 * * * cd /opt/orbitwork && docker compose run --rm app node dist/backup.js
# 同步到阿里云 OSS（示例，需安装 ossutil）
ossutil cp -r /var/lib/docker/volumes/orbitwork_orbit_data/_data/backups oss://your-bucket/orbitwork/

备份使用 VACUUM INTO，生成一致性快照；默认保留 14 天。不要直接复制 WAL 文件。

恢复

docker compose stop app caddy
docker run --rm -v orbitwork_orbit_data:/data -v $PWD:/backup alpine \
  sh -c "cp /backup/orbitwork-YYYY-MM-DD.db /data/orbitwork.db"
docker compose up -d

升级

git pull
docker compose up -d --build
# 迁移在启动时自动执行；失败则回滚镜像并恢复数据库备份

可观测性

  • 应用日志：Docker json-file；建议接入 Aliyun SLS，按 requestId/runId 检索。
  • 健康检查：app 与 sandbox 的 Compose healthcheck；Caddy 依赖 app healthy。
  • 关键指标建议：5xx 率、登录失败率、SSE 中断率、运行时长 P95、沙箱超时、安装成功率。
  • 安全：仅 80/443 暴露；SSH 限制源 IP；定期轮换 APP_SECRET 与管理员密码；不要把 .env 提交仓库。
21 · Scale

容量与演进

  • 当前容量：单节点 ≤200 活跃用户；SQLite WAL 单写者；LLM 延迟远大于 DB 写，实际瓶颈在模型与沙箱。
  • 纵向：4 vCPU / 8 GB 可覆盖多数团队；SSE 长连接需注意 Caddy/内核 fd 上限。
  • 横向：迁移 PostgreSQL（schema 可平移），Redis 存 session/rate limit，对象存储放备份；sandbox 改为独立队列消费者；SLB 前置多 app。
  • 多租户：所有表已有 workspace_id；未来可加 org/team 层级与配额。
不要直接多副本：SQLite 卷与内存限流均为单实例假设；无共享存储时启动两副本会导致数据分叉。需要先完成 PostgreSQL/Redis 改造。
